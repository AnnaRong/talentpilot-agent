# iTalent 关注候选人自动回锁

使用当前已登录的 iTalent 页面和 `ego-browser`。本 Skill 已包含所需安全与接口规则；执行前读取 [实时契约](references/contracts.md)。不得读取或保存 Cookie、Token、浏览器配置、完整简历或联系方式。

## 启用门槛

- 安装或首次调用后，必须先提醒用户配置本人的唯一承接岗位编号和目标阶段状态。未配置时只提示配置，不扫描、不写入。
- 承接岗位不是全局常量；每次运行都按编号实时唯一解析 `jobId/processId/phaseId/statusId`，并确认当前账号对岗位有权限。
- 不得在 Skill 中预置、默认或暗示任何真实岗位编号。测试环境中的岗位不是其他用户的默认值；其他 HR 可能没有权限。
- 配置岗位时，先向用户回显职位编号、职位名称、招聘类型、阶段状态和当前权限，得到明确确认后才保存为该用户的承接目标。
- 定时自动写入只适用于用户预先明确授权的承接岗位、阶段状态和运行范围。任何目标配置变化都使授权失效并暂停写入。

## 扫描

1. 打开“招聘管理系统 -> 首页 -> 我关注的应聘者”，从当前页面刚生成的关注列表请求读取全部分页，一次运行覆盖该用户当前全部关注记录，不设前 N 条默认上限。
2. 仅保留 `IsAttention=1`、`HasPermission=True`、未删除的候选人。只解析任务所需字段，不输出或保存手机号、邮箱、简历正文、Cookie、Token、短期签名或原始响应。
3. 读取关注候选人的实时标准锁状态。只有服务器当前状态明确未锁定才视为已解锁；操作记录中的七天期限和凌晨批处理时间只用于解释，不得替代实时状态。
4. 实时读取候选人现有申请和目标岗位冲突。目标岗位已存在申请、仍有推进中招聘流程、被其他岗位或人员锁定、招聘类型不匹配、无权限、状态矛盾或无法回读时跳过。
5. 来源招聘类型与承接岗位必须一致。不得把 `campus`、`internship` 和 `formal` 静默互转。

## 写入

对每名通过预检的候选人串行执行：

1. 重新读取关注状态、锁状态、目标岗位重复申请和承接岗位配置，生成状态指纹。
2. 发送推荐到职位请求，`isSkipApplyLock` 和 `isSkipApplicantLock` 始终为 `false`；页面接口不得添加绕锁字段。
3. 立即回读目标申请，必须同时确认同一候选人已进入实时解析的 `jobId/processId/phaseId/statusId`。
4. 每人结果独立记录；不确定响应先回读，不自动重发。冲突或失败跳过并通知，不影响其他候选人。

自动任务中，预授权只覆盖该用户明确配置的目标和上述守卫条件。不得扩展到新的候选人来源、不同招聘类型、其他岗位、其他阶段状态或任何淘汰/恢复操作。定时执行时间由用户单独配置，不能随 Skill 安装自动创建生产定时任务。

## 输出

报告本次服务器时间、关注人数、已解锁人数、成功、跳过和失败人数，并列出人名、稳定详情链接、目标岗位、阶段状态和人可读原因。只在成功、失败、需要人工处理或配置失效时通知；没有可处理变化时保持安静。
