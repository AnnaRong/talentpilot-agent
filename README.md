# iTalentPilot 招聘协作 Agent v0.6

最新能力、Comate 融合说明、实测结果与缺口见 [v0.5交付说明](docs/V0.5-COMATE-MERGE.md)。

这是可运行的本地应用，不是仅有说明的 Skill。当前定位是：

**自主只读采集任务链 + 持久化编排器 + 六个确定性专用模块 + 一个可选模型 Agent + 人工审批台。**

服务现在默认启用每天 11:00（Asia/Shanghai）的持久后台招聘流程。浏览器控制台只是监控与
人工审批界面，关闭页面不会停止任务；后台会按页面已有的 1 至 8 步逐项运行：北森只读、
多来源人才筛选、论文雷达、文件清洗与 JD 匹配、上传核验、锁提醒、漏斗和台账。登录、验证码、
未配置的平台以及简历上传/推荐等外部写入会进入明确的待处理状态，不会假装已经完成。
第 2 步会从每个岗位已核验的工作职责和任职资格自动生成搜索词、核心技能、经验范围、城市与
评分条件，并保存为每天 11:00 的逐岗配置；JD 未明确提供的年龄、薪资等条件不会推断。
监控中第 2 步继续展开为 2.1 JD 配置、2.2 BOSS直聘、2.3 公司系统与人才库、2.4 海外、
2.5 QQ邮箱；后台会核验可受控的 BOSS CLI/Ego Browser 登录会话。普通 Chrome 标签不会直接
交给后台脚本读取 Cookie；BOSS CLI 或 Ego Browser 会话登录失效时才提示本人处理。
运行时先检查已经打开且可受控的对应平台页面；只有未找到登录态时才打开新的登录页面。

选择 BOSS直聘、公司系统与人才库、海外或邮箱后，控制台先调用已批准的 LLM，按 Grill Me
方式一次询问一个问题，确认浏览器、具体任务、当前不正确之处和需要调整的流程，再进入平台工具。
文件整理中的“Jev 简历方向”使用 TypeSafe Jev 对脱敏简历与当前岗位 JD 做证据匹配，输出寻找方向
和需要补充的简历证据。LLM 或 Jev 未配置时流程明确阻断，不回退成伪模型结果。

不应称为“已全面接通北森/BOSS/如流的生产多 Agent”。外部连接尚未完成，
它们不会因为审批通过就返回“已发送”“已推荐”。详细差距见 `docs/ACCEPTANCE.md`。

## 安装与启动

需要 Python 3.10+；推荐 Python 3.12。解压后：

```sh
./install.sh
./start.command
```

本机打开 `http://127.0.0.1:8765/`。当前为单用户设计验证版本，不显示登录或密码，
打开页面后默认使用本地管理员身份。服务仍只监听本机地址，不能暴露公网或当作多人生产部署；
进入生产验收前必须恢复企业身份认证和权限隔离。

### BOSS 主动寻才

控制台的“BOSS直聘”入口支持 YAML 配置的多关键词搜索、年龄/经验/薪资/状态/活跃度硬筛、
跨关键词去重和 Top N 评分；可配置每天 11:00 常态运行，新岗位会同时重筛本地加密候选池。
配置示例位于 `config/boss-sourcing.example.yaml`。本机使用固定版本
`@viyzhu/boss-cli-fork@0.8.1`，浏览器必须保持有头模式；登录、验证码和安全验证由招聘者本人完成。
候选人审核清单加密保存在本机。招聘者可以从控制台打开可见的 BOSS 登录窗口；勾选候选人后，
系统先重新执行同一搜索，并通过 `greet --dry-run` 校验当前候选人和序号，招聘者再次明确确认后
才发送招呼。列表输出没有稳定候选人 ID，因此预览仅保持5分钟，发送前再次重查；页面变化、
风控或任一异常会立即停止，不自动重试。当前尚不自动索要简历或修改候选人状态。

依赖下载受网络限制时可设置企业批准的 `PIP_INDEX_URL` 后重跑安装。
打包文件不包含数据库、真实简历、真实 Excel、录屏、密钥或登录会话。

## 实际操作

控制台第一步只读取当前账号有权限的岗位。第二步选择岗位和最多100份 PDF、Word 或文本简历，
系统在临时目录解析姓名、手机号和邮箱，通过已授权的 iTalent“候选人信息查询”只读匹配，
按简历列出历史部门、岗位、最后投递时间、阶段状态、淘汰环节及录用时间。同岗位历史直接跳过，
锁定候选人跳过并提醒，身份冲突进入人工确认；其余候选人形成上传预览。

当前真实写入仍保持关闭：北森的新建应聘者页面已确认支持多简历、关联职位、默认渠道
`BOSS直聘`，但新建/更新简历、锁回读、真实 `简历复筛/进行中` 阶段 ID 和写后回读尚未完成
受控验真。点击确认会明确返回阻断，不会伪造上传成功。

公司人才库推荐已拆成两步：先在当前已登录的 Ego Browser 中逐人核验目标岗位名称、编号、
部门、`简历复筛/进行中`、既有申请和可用推荐表单，生成五分钟有效的确认指纹；再由用户
当轮确认后执行，并用 `GetJoblistOfApplicant` 逐人回读。生产推荐开关默认关闭，只有在隔离
测试岗位完成一次真实写入与回读验收后，才可在启动服务前设置
`ITALENT_RECOMMEND_WRITE_ENABLED=1`。响应不确定时不自动重试。

选择岗位后，“海外”入口可下载本机 LinkedIn 采集插件。插件仅在 HR 人工打开的
`https://www.linkedin.com/in/*` 公开个人主页工作，完整滚动并读取经历、教育、项目、技能、
语言与证书等可见字段；保存前必须填写地区、保留期限和合法处理授权依据。档案按岗位加密
保存在本机，控制台可勾选候选人并下载包含可编辑 DOCX、Markdown 和导出清单的 ZIP。
CAPTCHA、登录、安全验证和访问限制不会被绕过；真实 LinkedIn 账号链路仍需在授权环境验收。

“邮箱”入口会在 Ego Browser 打开所选邮箱的官方登录页，由收集人本人完成登录和验证码。
收集人点击“登录完成”后，Agent 接管同一任务空间，按所选岗位搜索邮件，只处理正文明确包含
求职/应聘意向且带 PDF 简历附件的邮件，自动下载、解析并按
`岗位名称+姓名` 保存到 `~/Desktop/简历/邮箱/<岗位>/`。无法可靠识别姓名的附件会跳过，
不猜测命名。系统不读取或保存邮箱密码、Cookie 和登录会话。

优先使用控制台顶部的“启动北森采集与审计”：管理员提交一次后，后台自行读取岗位、
申请和面试列表，校验并入库，调用审计模块，创建待审批 CSV 导出。页面关闭不取消后台任务；
服务必须保持运行。若登录失效或浏览器中断，在检查后点击“检查后继续”，不得绕过验证码。
暂停超过30分钟会重新采集，避免拼接过期断点。新安装需配置 Ego 并由本人登录北森。
详细说明和下列历史快照工作方式不同。

1. 本机管理员登录，点击“导入已核对快照”。读取 `data/live-captures/verified-latest.json`，
   必须通过 `talentpilot-ledger/2` 稳定 ID 和分页覆盖校验。全新安装没有真实数据，
   需先通过授权采集接入；不得将空表当成连接成功。
2. 选择数据集和“协作审计”。统计、面评分歧、锁检查、面试负载依次执行，
   任务、工具权限、调用预算、事件、记忆和结果持久化到本地 SQLite。
3. 时间源缺少时区时选择正确时区；未知时保持“未知，不换算”。这会明确报告缺失数，
   不会把未解析记录默认为当天零场。
4. 在结果中核对数据范围和缺口。缺少锁来源的任务状态是“已完成，有来源缺口”，
   不是“全流程完成”。Offer 未采集保持 `null`。
5. “导出当前统计 JSON”先发起审批，负责人核对不可变参数及哈希后批准，再执行。
   导出审批仅可消费一次。既有 Excel 下载需要本机管理员登录并留下审计记录，
   文件必须与当前快照的来源 SHA256 匹配。
6. BOSS、下载、上传、推进、超限排期和如流发布可登记审批要求，但没有真实适配器时
   执行结果固定为 `blocked`，且外部操作次数是零。

## 模型说明

- 配置中的默认模型名为 `gpt-5.6-sol`，这是网关路由名，不等于调用成功，也不构成
  对供应商实际底层模型身份的验证。
- 默认协作审计不使用 LLM，全部统计由 Python 确定性计算。
- 可选 `analyst` 需要 `LLM_API_KEY`、批准的 HTTPS `LLM_BASE_URL`、
  精确域名 `LLM_ALLOWED_HOST` 和 `LLM_EGRESS_ENABLED=1`。
- 管理员显式执行模型统计解释后，模型只能请求 `lookup_metric` 查询匿名岗位数字。
  最多 4 次请求，每次最多 800 输出 token；工具名和数字引用必须通过校验。
- 不发送候选人姓名、简历、面评或联系方式。文字解释仍为待人工核对草稿。
- 测试只使用 MockTransport 验证协议与越权拦截；真实网关尚未验收。

## 安全与边界

新增数据库中的证据、记忆、结果和同意记录使用 Fernet 加密；本机密钥不是企业 KMS。
旧的 `data/live-captures`、Excel、录屏、历史 SQLite 文件没有被自动迁移或加密。
本地保留期删除仅作用于同意记录库，不能声称删除了北森、旧报表或备份。

录屏默认关闭，只记录任务事件。之前原生录屏可能录到前台其他窗口，尚未有验证通过的
招聘任务专用视频；事件回放不等于视频。不要开启全屏录制来代替经过授权的页面录制。

单进程本地队列支持崩溃后按租约重试，不是 Redis/Kafka 分布式事件总线；
没有多租户 SSO、远程 KMS、完整删除链路、灾备、企业级监控或并发排期服务。
