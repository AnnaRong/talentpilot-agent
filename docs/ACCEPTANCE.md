# 需求核查与整改验收

> v0.4 已继续实现部分缺口，最新状态以 [V0.4-DELIVERY.md](V0.4-DELIVERY.md) 为准。
> 本文件下方是 v0.3 审计基线，保留用于前后对照。

核查日期：2026-09-21。范围：本地 TalentPilot Agent 实际代码、API、持久化状态和运行结果。

## 核心结论

旧版没有完成完整需求。“全流程”只是逐条记录描述，部分 Agent 名称并不对应实际执行；
不能把它当成已接通业务的多 Agent 平台。v0.3 补齐了一套可运行的本地混合系统，
但没有虚构或替代外部账号、企业 API、数据采购、合规审批和生产部署。

状态含义：
- **本地实现**：可由代码和本地测试验证。
- **部分实现**：仅部分输入/业务链路可用，限制仍然存在。
- **外部未验收**：不能计算为已接通或已完成。

## 修复的关键问题

1. 移除 `recruitment_workflow` 的描述性循环，禁止日志步骤冒充业务执行。
2. 关闭没有身份/参数绑定的旧审批；新审批必须绑定精确动作。
3. 保护 API，阻止跨域/跨站请求、未登录读取、非授权部门查询及任意路径输入。
4. 候选人分组不再使用文件名或序号作为唯一身份。
5. 模型配置不再被描述为实际模型调用；数据缺口、未知 Offer 与未接通外部接口明确展示。
6. 原生桌面录屏默认关闭，防止错误记录前台其他窗口。
7. 保留原始真实数据和旧导出，不用合成样例覆盖或混入生产快照。
8. 排除面评中的“页面未展示面评正文”和 `--` 占位项；无多面试官正文证据时，
   不把“检测到零分歧”解读成一致。无申请观察记录的岗位总量保持未知。

## 生产上线前必须验证

每项外部连接分别提供正式接口合同/工具清单、授权主体、租户和测试环境。
对真实写入，在人审确认的精确候选人/岗位/阶段上，必须先读、检查重复和锁、
校验审批、调用、读回；超时状态不明确时人工核查，不可盲目重试。

真实面评分析需招聘负责人授权，外发/跨境合规需公司法务确认。
本次的本地加密和审批门控不能替代这些条件。
