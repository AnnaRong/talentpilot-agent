# 本地 JD 匹配审核夹

## Jev 配置

匹配引擎固定为 TypeSafe AI Jev jev-1.13.0。从 TypeSafe 控制台创建 API Key 后，在项目根目录 .env 配置 TYPESAFE_API_KEY、TYPESAFE_EGRESS_ENABLED=1、TYPESAFE_BASE_URL=https://api.typesafe.ai/v1、TYPESAFE_MODEL=jev-1.13.0 和 TYPESAFE_CONFIDENCE_THRESHOLD=0.5。

重启本地服务后生效。未配置、服务失败或响应结构无效时整批失败，不回退到旧关键词算法。发送给 TypeSafe 的内容会先移除姓名标签、候选人姓名、电话、邮箱、身份证号和 URL；原始文件不会出站。高匹配要求 Jev 分数严格大于 70，同时核心技能和硬条件概率均不低于 0.7、最低置信度不低于 0.5，且级别为匹配或高于要求。

- 控制台第 4 区不再展示自动整理运行日志；后端状态、日志和原始归档保留。
- 点击“自动匹配全部岗位”后，系统读取当前北森岗位清单，逐个读取完整 JD，并自动映射已有本地岗位目录。
- Ego 只读打开当前岗位详情，按字段读取完整工作职责和任职资格；不保存动态签名 URL、Cookie 或 Token。
- Jev 使用 Score、Noul 和 Choice 并行评估整体匹配、核心技能、硬条件和岗位级别；最终门槛由本地确定性代码执行。
- “Jev 简历方向”将上述已验证信号转换为当前方向、相邻岗位方向及简历证据补充建议；它不替代用户的求职选择，也不作招聘决定。
- 无法可靠读取、正文不足 80 字或超过 10 MB 的文件列为解析失败并自动排除。扫描 PDF 没有自动 OCR，不能当作匹配结论。
- 高匹配原件只复制，不移动、不删除；保留文件名和来源日期子目录。同一岗位批次内相同哈希只复制一次。
- 输出为 `~/Desktop/简历/高匹配/<岗位名>-<J编号>/<时间>-<批次>/`，内含简历、岗位 JD 和 `自动匹配结果.html`；重复运行创建新批次，不覆盖旧结果。
- 北森存在同名但编号不同的岗位时，同一批本地简历会分别与每个岗位的独立 JD 匹配，并输出到按 J 编号隔离的目录。
- 匹配流程无需逐份人工确认；无法读取 JD、关键词不足、没有对应本地目录或简历无法解析时会单独列为缺口，不会猜测为合格。
- 批量历史核验前，后端检查文件哈希是否属于该岗位、同一 JD 和评分版本的已保存高匹配副本。现有北森外部上传仍保持关闭。

```sh
.venv/bin/python -m unittest discover -s tests -v
TALENTPILOT_URL=http://127.0.0.1:8769 .venv/bin/python scripts/verify_resume_matching_ui.py
```

界面验证使用合成 API 响应，不执行北森写入。真实审核文件另行核对副本哈希与每个文件链接。
