# 候选人锁提醒接入

## 已实现

- 原“只读巡检计划”替换为候选人锁提醒台，按上传关联、我的招聘、关注回捞分组。
- 只读刷新关注清单和当前招聘流程的全部申请分页；完整覆盖成功后才替换本地观察结果。
- 上传核验中的可靠单一身份被锁记录自动进入监测，明确标识“核验被锁，未上传”。
- 预计解锁倒计时、提前提醒、原岗位掉锁检测、实时解锁提醒、站内收件箱和已读状态。
- 缺失时间或时区、过期观察、权限缺失、离开采集范围分开呈现。预计时间到期不等于服务器已解锁。
- 设置检查间隔和提前提醒时间；默认暂停，启用后由本地持久化 worker 执行只读采集。
- 监测名单和提醒加密存储、按本地操作者隔离，提醒去重；外部写入没有自动重试。
- 压缩包原文保留在 `integrations/italent-followed-applicant-relock/`。
- 回捞核验单绑定候选人、目标岗位、阶段状态、指纹及有效期；未验真的外部写入阻断。

## 真实验证与边界

2026-09-23 的只读验收完整读取当前“百度社招实习生招聘流程 / 招聘中职位”
的 1,495 条申请，识别 204 条当前职位锁记录。关注清单完整返回 0 条。
这不是全公司、所有招聘类型或全部流程的清单，也不等于每个岗位由当前操作者独占负责。

本次 204 条锁记录的 `PredictUnlockTime` 没有返回有效的明确时区时间。
它们全部显示“时间 / 状态待核实”，不能承诺真实倒计时已可用。
没有采用操作记录加七天等推断，也没有把缺失时间当成已解锁。

目前应用原有的简历上传仍是核验预览，不会产生“上传成功”回执。
因此上传分组现在接收的是上传核验被锁记录，不声称已完成外部上传。
该分组只有关联到当前关注清单时才自动刷新候选人级锁状态；其他记录会过期并要求核实。

压缩包是 Skill 规则与页面契约文档，没有可直接运行的写入适配器。
应用已接入本地回捞核验单；真实推荐、流程 ID 解析与逐人回读尚未在该应用验真，
确认接口仍返回 `blocked` 和 `external_actions: 0`。没有执行推荐、续锁、恢复或淘汰。
承接岗位和目标阶段不得从历史账号或测试数据默认继承。

通知仅在本站内显示，不发送如流、邮件或系统推送。
本地服务关闭或机器休眠期间不会执行定时采集。
当前仍为 loopback 单用户设计模式；正式上线前必须恢复认证和组织权限隔离。
